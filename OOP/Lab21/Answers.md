# Відповіді на контрольні запитання (20. Стан)

## 20.1.1. Для чого застосовується шаблон Стан?
Щоб об'єкт змінював свою поведінку залежно від внутрішнього стану так, ніби
змінюється його клас. Замість громіздких умовних конструкцій (switch/if по
полю-стану), що розкидані по методах, кожен стан виноситься в окремий клас із
власною поведінкою. Переваги: усунення великих switch/if, локалізація логіки
кожного стану, спрощення додавання нових станів (OCP), явні переходи між станами.

## 20.1.2. Основні етапи реалізації:
1. Оголосити інтерфейс стану з методами, що відповідають діям, поведінка яких
   залежить від стану.
2. Для кожного стану створити окремий клас, що реалізує цей інтерфейс і містить
   поведінку та переходи в інші стани.
3. У контексті зберігати посилання на поточний об'єкт-стан і метод його зміни.
4. Методи контексту делегують виклики поточному стану.
5. Стани (або контекст) ініціюють переходи, замінюючи поточний стан контексту
   на інший.
