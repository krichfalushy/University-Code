# task_3_1 — Адаптер USB Type-C <-> micro-USB

Адаптер для заряджання Type-C телефона (SamsungS) старою micro-USB зарядкою.

Реалізовано:
- `AdapterMicroUsbToTypeC` — через композицію (агрегує MicroUsbCharger).
- `AdapterMicroUsbToTypeCInheritance` — через наслідування (extends Charger implements TypeCCharger).
- `AdapterTypeCToMicroUsb` — ЗВОРОТНИЙ адаптер (Type-C -> micro-USB), щоб старим MobilePhone користуватись новою зарядкою.

Запуск: `javac -cp libs/MicroUsb.jar src/*.java && java -Dstdout.encoding=UTF-8 -cp "src:libs/MicroUsb.jar" Main`

## Відповідь на питання (для коментаря до розв'язку)
Так, для цієї задачі можна створити ДВОСТОРОННІЙ адаптер, і він реалізований
(AdapterMicroUsbToTypeC у прямому напрямку + AdapterTypeCToMicroUsb у зворотному).
Проте напрямки НЕ симетричні за повнотою інформації:
- micro-USB -> Type-C: перетворення коректне без втрат. micro-USB надає напругу (V)
  і струм (A), а потужність Type-C обчислюється як P = V * A — усі дані є.
- Type-C -> micro-USB: перетворення неоднозначне. Type-C віддає лише сумарну
  потужність P (getOutputPower), а micro-USB-контракт вимагає ОКРЕМО напругу і струм.
  Одне значення P розкладається на пару (V, A) нескінченною кількістю способів,
  тому адаптер змушений прийняти припущення про номінальну напругу (5 В стандарт
  micro-USB) і вивести струм як I = P / U.
Висновок: двосторонній адаптер можливий, але «зворотний» бік вносить припущення
через втрату інформації (Type-C абстрагує V та A в одну величину P). Технічно
двосторонній адаптер реалізують або одним класом, що імплементує обидва інтерфейси,
або двома окремими адаптерами (як тут).
