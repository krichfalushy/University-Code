# Відповіді на контрольні запитання (16. Ітератор)

## 16.1.1. Для чого застосовується шаблон Ітератор?
Щоб надати спосіб послідовного доступу до елементів складеного об'єкта
(колекції) без розкриття його внутрішньої структури. Переваги:
- клієнт обходить колекцію однаково, не знаючи, як вона влаштована
  (масив, список, дерево, геш-таблиця);
- можна мати кілька незалежних обходів однієї колекції одночасно та різні
  порядки/стратегії обходу (напр., за алфавітом, за спаданням, DFS, BFS);
- логіка обходу виноситься з колекції в окремий об'єкт (SRP).

## 16.1.2. Основні етапи реалізації:
1. Оголосити інтерфейс ітератора з методами hasNext() та next()
   (у Java — java.util.Iterator).
2. Реалізувати конкретний ітератор, що зберігає позицію обходу й знає,
   як перейти до наступного елемента конкретної колекції.
3. Оголосити інтерфейс колекції з методом створення ітератора
   (у Java — Iterable.iterator()).
4. Реалізувати створення ітератора у конкретній колекції.
5. Клієнт отримує ітератор від колекції та перебирає елементи через
   hasNext()/next() (або через цикл for-each, що використовує їх неявно).
