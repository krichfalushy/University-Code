# Лабораторна робота №3 — MPI. Моделювання процесів на полігональних поверхнях

Паралельне моделювання перенесення теплової енергії по поверхні меш-моделі.
Мова — Python 3 (numpy + numpy-stl + mpi4py), обмін — MPI.

```
lab3/
├── src/mesh_tools.py     меш: генерація, STL, сусідство, геометрія, BFS
├── src/heat_mpi.py       паралельне моделювання теплопровідності
├── tools/make_mesh.py    створення сфери та запис у STL
├── tools/render.py       картинки поширення тепла та схема розбиття
├── tools/plot_speedup.py графік прискорення та ефективності
├── run_bench.sh          заміри на 1..N процесах + графік
├── data/sphere.stl       меш-модель (81 920 трикутників)
└── results/              картинки, таблиця, CSV
```

## 1. Встановлення

```bash
sudo apt update
sudo apt install -y build-essential openmpi-bin libopenmpi-dev python3-pip
pip3 install numpy numpy-stl mpi4py matplotlib
```

**macOS (зокрема Apple Silicon M1–M4):**
```bash
xcode-select --install          # якщо ще не стояло
brew install open-mpi
python3 -m venv ~/venv && source ~/venv/bin/activate
pip install numpy matplotlib numpy-stl
pip install --no-binary=mpi4py mpi4py
```

Останній рядок важливий: готове «колесо» mpi4py з PyPI зібране зі своєю
власною збіркою MPI, і тоді `mpirun -np 4` мовчки запустить чотири
НЕЗАЛЕЖНІ однопроцесні програми замість однієї паралельної. Ключ
`--no-binary` змушує зібрати mpi4py проти того MPI, що поставив brew.

Перевірка, що зв'язка працює:
```bash
mpirun -np 4 python3 -c "from mpi4py import MPI; print(MPI.COMM_WORLD.Get_rank(), MPI.COMM_WORLD.Get_size())"
```
Має надрукувати чотири рядки з другим числом `4`. Якщо друге число `1` —
mpi4py та mpirun із різних збірок MPI, перевстановіть із `--no-binary`.


## 2. Запуск — три команди

```bash
# 1. створити меш-модель (сферу) і зберегти у STL
python3 tools/make_mesh.py --subdiv 6 --out data/sphere.stl --halo-report

# 2. промоделювати на 4 процесах, зберегти кадри та історію
mpirun -np 4 python3 src/heat_mpi.py data/sphere.stl --steps 4000 --check \
       --out results/field.npz --history results/history.csv

# 3. намалювати картинки
python3 tools/render.py --npz results/field.npz --mesh data/sphere.stl \
       --history results/history.csv --outdir results --procs 8
```

Дослідження масштабованості з графіком прискорення:

```bash
STEPS=4000 TRIALS=3 ./run_bench.sh data/sphere.stl
```

Скрипт сам визначає кількість ядер (`nproc`), проганяє всі P від 1 до nproc
для двох порядків нумерації граней і створює `results/speedup.png`,
`results/table.md`, `results/scaling.csv`.

### Параметри `heat_mpi.py`

| Параметр | Призначення |
|---|---|
| `--steps N` | кроків за часом (типово 2000) |
| `--alpha A` | коефіцієнт температуропровідності, м²/с (типово 1e-3) |
| `--cfl C` | запас стійкості, частка граничного кроку (типово 0.4) |
| `--t0 T` | початкова температура поверхні, °C (типово 20) |
| `--thot T` | температура гарячого полігона, °C (типово 100) |
| `--order bfs` | компактні частини (перевпорядкування обходом у ширину), типово |
| `--order file` | частини в порядку граней із файлу — для порівняння |
| `--out файл.npz` | зберегти кадри температури, сітку та геометрію |
| `--history файл.csv` | зберегти T(t) і теплову енергію |
| `--ref файл.npz` | звірити кінцеве поле T з еталонним запуском |
| `--diag-every N` | через скільки кроків писати T(t); `0` — вимкнути (чисті заміри) |
| `--check` | друкувати перевірки збереження енергії та принципу максимуму |
| `--csv`, `--tag` | дописати час виконання у CSV |

### Розмір меша

`--subdiv N` дає `20 * 4**N` трикутників:

| subdiv | трикутників | застосування |
|---:|---:|---|
| 4 | 5 120 | швидка перевірка |
| 5 | 20 480 | картинки |
| 6 | 81 920 | основна модель, заміри |
| 7 | 327 680 | велика модель (потрібно більше пам'яті й часу) |

Замість сфери можна взяти будь-який інший STL — програма приймає готовий
файл і сама будує сусідство.

## 3. Як це влаштовано

### Меш і атрибути

Сфера будується поділом ікосаедра: кожен трикутник ділиться на чотири, нові
вершини виносяться на сферу. Трикутники виходять майже однаковими за площею
(у 81 920-гранній моделі площі різняться лише в 1.3 раза).

Модель зберігається у **STL** і читається назад через `numpy-stl`. У STL
кожен трикутник записаний трьома власними вершинами, тому спільні вершини
дублюються і топології немає. Програма «зварює» вершини — зводить однакові
координати до одного індексу, — і лише після цього може побудувати сусідство.

**Атрибут температури** — один масив `float64` довжиною в кількість граней.
Початково всюди 20 °C, в одного трикутника 100 °C.

**Атрибут сусідства** — масив `(nf, 3)`: для кожного трикутника номери трьох
сусідів через кожне його ребро. Будується так: кожне ребро кодується парою
впорядкованих номерів вершин, ребра сортуються, і ті, що трапилися двічі,
дають пару сусідніх трикутників. На замкненій сфері всі три сусіди є завжди;
для відкритої моделі відсутній сусід позначається `-1` і межа вважається
теплоізольованою.

### Схема теплопровідності

Метод скінченних об'ємів на дуальному графі меша:

```
A_i · dT_i/dt = alpha · Σ_j w_ij · (T_j − T_i),     w_ij = L_ij / d_ij
```

де `A_i` — площа трикутника, `L_ij` — довжина спільного ребра, `d_ij` —
відстань між центрами. Явний крок Ейлера; крок за часом обирається з умови
стійкості `dt ≤ min_i A_i / (alpha · Σ_j w_ij)` із запасом CFL.

Оскільки `w_ij = w_ji`, скільки тепла пішло з одного трикутника, стільки
прийшло в сусідній: схема **точно зберігає** сумарну теплову енергію
`Σ A_i·T_i`. Це використано як перевірка.

### Паралелізація

1. Ранг 0 читає меш, будує сусідство й геометрію.
2. Грані перевпорядковуються обходом у ширину по дуальному графу, після чого
   неперервний блок граней — це зв'язна ділянка поверхні.
3. Блоки роздаються процесам через `Scatterv` (кожен процес тримає лише свою
   частину моделі).
4. Кожен процес визначає своє «гало» — чужі трикутники, що межують із його
   ділянкою, — і через `Alltoall`/`Alltoallv` домовляється, хто кому що
   надсилає. План будується один раз.
5. На кожному кроці: обмін температурами гало через `Isend`/`Irecv` **лише з
   сусідніми по поверхні процесами**, далі векторизоване оновлення температур.

Чому важливе перевпорядкування: у вихідному порядку граней STL сусідні за
номером трикутники розкидані по всій сфері, тож при 8 процесах кожному
потрібні 30 720 чужих трикутників. Після обходу в ширину — 643, у 48 разів
менше.

## 4. Перевірки коректності

Програма з ключем `--check` друкує три перевірки:

1. **Збереження енергії**: `|E(t) − E(0)| / E(0)` ≈ 1e-15, тобто на рівні
   похибки округлення.
2. **Принцип максимуму**: температура завжди лишається в межах
   `[20 °C, 100 °C]` — нефізичних викидів немає, крок за часом стійкий.
3. **Збіг результатів при різній кількості процесів**: ключ `--ref` звіряє
   кінцеве поле температур з еталонним запуском. Збіг **побітний**, бо жоден
   трикутник не ділиться між процесами і порядок підсумовування не залежить
   від P.

Додатково: рівноважна температура, до якої сходиться поле, збігається з
аналітичною `Σ A_i·T_i(0) / Σ A_i`.
