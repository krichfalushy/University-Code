# Лабораторна робота №4 — OpenMP. Прогнозування за рухомим середнім

Паралельний розрахунок простого (SMA) та зваженого (WMA) рухомого середнього
за вікном довжиною N, прогноз ціни на наступний торговий день, оцінка похибки
та порівняння швидкодії на 1..N потоках. Мова — C (C99) + OpenMP.

```
lab4/
├── src/forecast_omp.c      головна програма
├── Makefile                збірка (сам знаходить libomp на macOS)
├── get_data.sh             завантаження котирувань зі Stooq
├── run_bench.sh            заміри на 1..N потоках + графік прискорення
├── tools/plot_results.py   графіки точності, прогнозу та прискорення
├── data/vix-daily.csv      CBOE VIX, щоденно з 1990 (36 років)
├── data/brent-daily.csv    нафта Brent, щоденно з 1987 (39 років)
└── results/                графіки, таблиці, CSV
```

## 1. Встановлення

**Ubuntu / Debian / WSL:**
```bash
sudo apt update
sudo apt install -y build-essential python3-matplotlib
```
GCC підтримує OpenMP «з коробки», нічого окремо ставити не треба.

**macOS (зокрема Apple Silicon M1–M4):**
```bash
xcode-select --install
brew install libomp
pip3 install matplotlib
```
Apple clang **не має** OpenMP із коробки — саме для цього потрібен `libomp`.
Makefile сам його знайде і підставить потрібні ключі; якщо бібліотеки немає,
збірка зупиниться із зрозумілим повідомленням.

## 2. Запуск — дві команди

```bash
make
./forecast_omp data/vix-daily.csv --threads 4 \
     --sweep results/sweep.csv --series results/series.csv --series-window 20
```

Програма надрукує похибки та найкращі вікна, а також запише:
`results/sweep.csv` — похибки для кожної довжини вікна, `results/series.csv` —
ряд прогнозів для одного вікна.

Графіки:
```bash
python3 tools/plot_results.py --sweep results/sweep.csv \
        --accuracy results/accuracy.png \
        --series results/series.csv --forecast results/forecast.png --window 20
```

Порівняння швидкодії та графік прискорення:
```bash
REPEAT=10 TRIALS=3 ./run_bench.sh data/vix-daily.csv
```

Скрипт сам визначає кількість ядер, проганяє всі значення потоків від 1 до
цього числа для обох режимів паралелізації і створює `results/speedup.png`,
`results/table.md`, `results/scaling.csv`.

### Параметри програми

| Параметр | Призначення |
|---|---|
| `--wmin N` / `--wmax N` | діапазон довжин вікна (типово 2..252) |
| `--threads T` | кількість потоків OpenMP (0 — за замовчуванням системи) |
| `--parallel days` | потоки рахують різні дні в межах одного вікна (типово) |
| `--parallel windows` | потоки рахують різні довжини вікна |
| `--repeat R` | повторити розрахунок R разів (стабільніші заміри часу) |
| `--sweep файл.csv` | похибки для кожної довжини вікна |
| `--series файл.csv` | ряд прогнозів для одного вікна |
| `--series-window N` | яке саме вікно зберегти в `--series` (типово 20) |
| `--from` / `--to` | обмежити період, формат `YYYY-MM-DD` |
| `--date-col` / `--price-col` | назви колонок, якщо не вгадалися автоматично |
| `--csv` / `--tag` | дописати час виконання у CSV для бенчмарку |

У комплекті дві реальні біржові серії, обидві в межах «10–50 років»:

| Файл | Інструмент | Період | Днів |

Колонки шукаються за назвою в заголовку, тому формати Stooq, Yahoo Finance та

вкажіть їх явно: `--date-col Data --price-col Zamkniecie`.

## 4. Що саме рахує програма

Прогноз ціни на день `t+1` будується за останніми N днями:

```
SMA:  f[t+1] = (p[t] + p[t-1] + ... + p[t-N+1]) / N
WMA:  f[t+1] = (N*p[t] + (N-1)*p[t-1] + ... + 1*p[t-N+1]) / (N + (N-1) + ... + 1)
```

У простому середньому всі дні вікна рівноправні; у зваженому новіші ціни
важать більше, тому WMA менше запізнюється за ціною.

Похибки рахуються проти фактичної ціни наступного дня: MAE, RMSE, MAPE, а
також частка випадків, коли вгадано **напрямок** руху ціни. Окремо
обчислюється «наївний» прогноз `f[t+1] = p[t]` — для біржових рядів це дуже
сильний орієнтир, і будь-який метод має сенс порівнювати саме з ним.

Усі довжини вікна оцінюються на **одному й тому ж** наборі днів (починаючи з
дня `wmax`), інакше порівняння різних N було б нечесним.

## 5. Паралелізація

Два режими, між якими перемикає `--parallel`:

| Режим | Що виконують потоки | Входів у паралельну область |
|---|---|---:|
| `days` (типово) | різні **дні** в межах однієї довжини вікна | 251 |
| `windows` | різні **довжини вікна** | 1 |

Обидва дають **побітно однаковий** результат за будь-якої кількості потоків:
прогнози спершу складаються в масив паралельно, а підсумкові суми похибок
обчислюються послідовно у фіксованому порядку. Якби замість цього
використовувалася `reduction(+:...)`, результат залежав би від кількості
потоків у останніх розрядах.

Режим `windows` помітно ефективніший: одна паралельна область замість 251,
а `schedule(dynamic)` вирівнює навантаження (робота для вікна N росте як N).
