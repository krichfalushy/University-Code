# Лабораторна робота №2 — MPI. Паралельне множення розрідженої матриці на вектор

Реалізація алгоритму з праці G. Blelloch, *Programming Parallel Algorithms*,
CACM 39(3), 1996, розд. 3.2 «Sparse Matrix Multiplication»
(<https://www.cs.cmu.edu/~scandal/cacm/node9.html>) у моделі передавання
повідомлень MPI. Мова — C (C99), збірка `mpicc`.

Основна матриця: **wiki-Vote** — мережа голосувань за адміністраторів
Вікіпедії, 7 115 × 7 115, 103 689 ненульових елементів
(<https://snap.stanford.edu/data/wiki-Vote.html>; у базі SuiteSparse —
`SNAP/wiki-Vote`, <http://sparse.tamu.edu/SNAP/wiki-Vote>).

```
lab2/
├── src/spmv_mpi.c        головна програма (C99 + MPI)
├── Makefile              збірка
├── data/wiki-Vote.txt    матриця (список ребер SNAP)
├── get_matrix.sh         завантаження інших матриць із SuiteSparse
├── run_bench.sh          запуск на 1..N процесах + побудова графіка
├── tools/plot_speedup.py графік прискорення та ефективності
├── tools/gen_matrix.py   синтетична велика матриця (для перевірки на великих даних)
└── results/              scaling.csv, table.md, speedup.png
```

## 1. Що потрібно встановити

**Ubuntu / Debian / WSL:**
```bash
sudo apt update
sudo apt install -y build-essential openmpi-bin libopenmpi-dev python3-matplotlib
```

**Fedora / RHEL:**
```bash
sudo dnf install -y gcc make openmpi openmpi-devel python3-matplotlib
module load mpi/openmpi-x86_64        # щоб з'явився mpicc
```

**macOS (зокрема Apple Silicon M1–M4):**
```bash
xcode-select --install          # якщо ще не стояло
brew install open-mpi
pip3 install matplotlib         # потрібен лише для графіка
```

## 2. Запуск — дві команди

```bash
make                                                      # збірка
mpirun -np 2 ./spmv_mpi data/wiki-Vote.txt --reps 20000 --check
```

Повне дослідження масштабованості з графіком:

```bash
REPS=20000 TRIALS=5 ./run_bench.sh data/wiki-Vote.txt
```

Скрипт сам визначає кількість ядер (`nproc`), проганяє всі P від 1 до nproc
для обох схем обміну і створює `results/speedup.png`, `results/table.md`,
`results/scaling.csv`.

### Параметри програми

| Параметр | Призначення |
|---|---|
| `--reps N` | повторень множення для усереднення часу (типово 100) |
| `--check` | перевірити результат послідовним множенням на ранзі 0 |
| `--comm sparse` | обмін лише потрібними компонентами `x` (`MPI_Alltoallv`), типово |
| `--comm allgather` | наївний обмін усім вектором (`MPI_Allgatherv`) — для порівняння |
| `--partition nnz` | розбиття рядків, збалансоване за ненульовими елементами, типово |
| `--partition rows` | наївне розбиття порівну за кількістю рядків — для порівняння |
| `--weights unit` | ваги ребер = 1 (матриця суміжності), типово |
| `--weights rand` | псевдовипадкові ваги ребер у [−1, 1] |
| `--csv файл` | дописати рядок результатів у CSV |
| `--tag назва` | мітка запуску в CSV |
| `--seed S` | зерно генератора вектора `x` (типово 42) |
| `--save-y файл` | зберегти вектор-результат `y` |

## 3. Підтримувані формати вхідних даних

Формат розпізнається за першим рядком файлу.

1. **Matrix Market** (`.mtx`) — рідний формат SuiteSparse:
   `coordinate`, поле `real` / `integer` / `pattern`, симетрія
   `general` / `symmetric` / `skew-symmetric` (нижній трикутник
   автоматично дзеркалиться).
2. **Список ребер SNAP** — рядки «FromNodeId ⇥ ToNodeId», коментарі з `#`.
   Номери вузлів перенумеровуються у 0..n−1.

### Інші матриці з SuiteSparse

`./get_matrix.sh <Група> <Назва>` завантажує tar.gz і кладе `.mtx` у `data/`:

| Група / назва | Розмір | nnz | Тип задачі |
|---|---|---|---|
| `SNAP wiki-Vote` | 7 115 | 103 689 | граф голосувань (ця робота) |
| `Boeing pwtk` | 217 918 | ≈ 11,5 млн | конструкційна механіка |
| `Williams consph` | 83 334 | ≈ 6,0 млн | МСЕ, сферична оболонка |
| `Freescale Freescale1` | 3 428 755 | ≈ 17,1 млн | схемотехніка, несиметрична |

Велика синтетична матриця (МСЕ-подібна, без інтернету):
```bash
python3 tools/gen_matrix.py --n 60 --out data/big.mtx   # 216 000 рядків, 5,6 млн nnz
```

## 4. Що саме робить програма

1. **Ранг 0** читає файл і будує CSR (перетворення COO → CSR двома стійкими
   сортуваннями підрахунком: за стовпцем, потім за рядком).
2. Рядки розподіляються між процесами неперервними блоками, збалансованими
   **за кількістю ненульових елементів** (бінарний пошук у масиві префіксних
   сум `row_ptr`) — для графів зі степеневим розподілом степенів це істотно.
3. Фрагменти CSR роздаються через `MPI_Scatterv`.
4. Будується **план розрідженого обміну**: кожен процес визначає, які чужі
   компоненти `x` йому потрібні, через `MPI_Alltoall`/`MPI_Alltoallv`
   домовляється з рештою, а локальні номери стовпців перенумеровуються так,
   щоб ядро працювало зі суцільним локальним вектором.
5. Кожна ітерація: обмін компонентами `x` → локальне множення
   `y[i] = Σ val[k]·x[ci[k]]` — це і є вираз Блеллоха
   `{sum({v * x[i] : (i,v) in row}) : row in A}`.
6. `--check` збирає `y` на ранзі 0 і порівнює з послідовним множенням.
   Похибка точно нульова, бо рядки не діляться між процесами й порядок
   підсумовування не змінюється.

## 5. Якщо потрібен графік на 8–16 ядрах

`run_bench.sh` працює на будь-якій Linux-машині без змін. Щоб крива мала
більше точок, потрібна машина з 8–16 **фізичними** ядрами: запускати більше
процесів, ніж є ядер, сенсу не має — прискорення виходить на насичення.
Найдешевший шлях — погодинна оренда хмарної машини: дві години роботи
коштують копійки, а після `./run_bench.sh` її можна одразу видалити.
